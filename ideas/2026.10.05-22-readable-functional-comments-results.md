## Comment Work

### Group A

Main, BaseTool, CardEntities, SparklineGraphTool, SparklineHistory and SparklineSeries received fresh explanations based on uncommented code and its actual callers. Afterward, the previous comments were checked for missing facts.

The comments explain, for example:

- HA entity-object changes matter even when formatted states compare equal.
- Sparklines update first, followed by fhs_sparkline values and the Text, State, Horseshoe and Control tools that use them.
- History requests use each Series' source timestamps while every Series uses the same visible graph timeline.
- A live update converts changed measurements; unchanged graph rows keep their previous conversion.
- Active marker and tooltip positions are recalculated after graph, layout and mounted-SVG changes.
- Graphs keep existing measurements and configuration on ordinary HA updates.
- SVG color layers are clipped by line/area/min-max masks, with individual Series value ranges.
- Browser-measured legend text determines the reserved graph space.

The two approved Group A examples, path-geometry.js and icon-svg-source.js, retained their useful wording. They were not generically rewritten.

### Group B and Review-Only Modules

Clear existing comments were retained. Abstract explanations were replaced with concrete HA/FHS descriptions; brief context was added where behavior was otherwise hard to follow.

Preserved explanations include:

- SAK color-stop examples and HA websocket/registry/theme details.
- Rounded rectangle/polygon side numbering and corner calculations.
- Safari's exact-endpoint round-cap workaround, including its inline 0.001 explanation.
- Center-marker order: correct the icon's rotation, measure the corrected shape, apply its aspect ratio, then place it along the current direction.
- SVG y-axis direction, group transforms and independent text/icon orientation.
- Existing text measurement, ellipsis, action and unavailable-state details.

Removed noise includes obsolete claims that a used style method was unused, commented-out experiments, large section banners and comments that merely restated an assignment or return.

The third approved example, text-tool-geometry.js, kept its functional explanation. Its wording was clarified to describe the measured center and size for Name, Area, State and Text.

All reported comment findings were incorporated:

- History request-start/status changes also refresh fhs_sparkline values, not only completed responses.
- A real-time bar/equalizer default color-stop scale replaces both Y bounds.
- Static radial settings are checked when concrete; JavaScript settings are checked after evaluation.
- A saved barcode event target is used during gestures; graph/layout changes recalculate pointer coordinates.
- State-band labels belong inside their bands.
- Reconnect marks active History ranges for the next HA update while loaded rows remain available.
- Hidden width-measurement text must finish before visible legend height is measured; its bounding box already uses local SVG units.
- Cached conversion follows an equivalent fresh HA entity, allowing a later correction to replace the right graph row.
- Original HA time distinguishes repeated winter-hour measurements projected onto the same graph time.
- Older Icon requests can neither replace a newer icon nor clear a newer pending request.
- Successfully loaded palettes survive disconnect; interrupted loads are retried.
- Referenced Text width/height includes twice the configured padding.
- Default Number increment/decrement targets differ from custom actions; local FHS values are also supported.
- Template default_entities merges precede filtering and final slot indexing.
- Empty History is a successful result distinct from waiting for rows.
- Negative path offsets use the opposite of the named side.
- External palette/CSS colors must be available before gradient comparison keys are stored.

These were comment corrections only. No separately actionable functional defect was reported during this work.

## Reproducible Source Check

Save the following verifier outside the product sources and invoke it with the candidate repository and a baseline checkout. Acorn is loaded from the candidate's installed dependencies.

```js
const fs = require('node:fs');
const path = require('node:path');
const { createRequire } = require('node:module');
const [root, baseline] = process.argv.slice(2);
const { parse, tokenizer } = createRequire(path.join(root, 'package.json'))('acorn');
const options = { ecmaVersion: 'latest', sourceType: 'module' };
const protectedText = /eslint|@ts-|@type\b|@typedef|@template\b|istanbul|\bc8\b|__PURE__|__NO_SIDE_EFFECTS__|@license|@preserve|copyright|SPDX|Licensed under|Apache License|MIT License|sourceMappingURL|sourceURL|vite-ignore|webpack/i;
const positions = (key, value) => ['start', 'end', 'loc', 'range'].includes(key) ? undefined : value;
const tokens = source => Array.from(tokenizer(source, options), token =>
  [token.type.label, source.slice(token.start, token.end)]);
const protectedComments = comments => comments.filter(comment =>
  protectedText.test(comment.value)).map(comment => comment.value);
let count = 0;
for (const name of fs.readdirSync(path.join(root, 'src')).filter(name => name.endsWith('.js')).sort()) {
  const before = fs.readFileSync(path.join(baseline, 'src', name), 'utf8');
  const after = fs.readFileSync(path.join(root, 'src', name), 'utf8');
  const beforeComments = [];
  const afterComments = [];
  const beforeAst = parse(before, { ...options, onComment: beforeComments });
  const afterAst = parse(after, { ...options, onComment: afterComments });
  if (JSON.stringify(tokens(before)) !== JSON.stringify(tokens(after))) throw Error(name + ': tokens differ');
  if (JSON.stringify(beforeAst, positions) !== JSON.stringify(afterAst, positions)) throw Error(name + ': AST differs');
  if (JSON.stringify(protectedComments(beforeComments)) !== JSON.stringify(protectedComments(afterComments))) throw Error(name + ': directives differ');
  count += 1;
}
console.log(count + ' modules match');
```
