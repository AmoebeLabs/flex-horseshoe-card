## 1. Goal

Make replacement/disconnect reliably reach each resource-owning object's cleanup path before specialized pointer/Horseshoe work is refined later.

Rule:

```text
creator owns handle/reference -> creator cleanup stops/removes it
```

## 2. Prerequisites

Plans 01–04 complete so Sparkline History/Series/Graph ownership will not move again while lifecycle cleanup is wired.

## 3. Current-code validation

Inventory the complete `src` tree for timers, intervals, RAFs, global listeners, observers, animators, async owner identities and nested lifecycle-aware children. Verify tool replacement paths in `CardTools`, horseshoe replacement and parent disconnect/reconnect order.

The current code confirms these gaps: CardTools replaces section arrays without closing their tools; Horseshoe owns an animator but does not stop it on disconnect; Sparkline leaves pointer listeners/frames alive; Slider cancels handles without resetting interaction state; composite controls only forward part of their lifecycle. History already invalidates requests and cancels timers. Its existing request identity remains the authority for accepting completions.

## 4. Scope

- old tool instances are closed before replacement;
- new tools receive the already-current lifecycle notifications when parent remains connected;
- History owner cleanup is reached and its timers/request relevance end;
- cleanup is idempotent;
- composite owners forward cleanup to nested resource owners;
- existing Horseshoe animator and Sparkline pointer cleanup hooks are invoked where current handles already exist.

## 5. Out of scope

- fixing pointer captured-state/node-lifetime bugs (Plan 09);
- fixing arbitrary-progress path-cache growth or animator target semantics (Plan 10);
- palette/ChildCards stale completion rules (Plan 06).
- untracked icon retries, delayed text measurements and other non-History completions (Plan 06);
- internal `setHass()` propagation (Plan 07).

This plan establishes the permanent cleanup route that those plans extend; it does not add a temporary resource manager.

## 6. Required replacement order

```text
old tools
 -> oldTool.disconnected()/concrete cleanup
 -> release old references
 -> construct/assign new tools
 -> give new tools current connected/HA lifecycle if parent is already active
```

Apply the same old-before-new rule to Horseshoe and other separately replaced instances.

## 7. Implementation sequence

1. #690: commit this reviewed plan and inventory, close old CardTools arrays before replacement, and activate new tools with the current parent lifecycle. Result: replacement has the same cleanup route as disconnect.
2. #691: stop History timers/requests, Horseshoe animation, Sparkline pointer listeners/frames and Slider interaction resources through their owners. Reset released handles and interaction state. Result: closed owners cannot continue their work or execute a final user action.
3. #692: forward lifecycle to direct and composite control children; close old content before rebuilding it and activate new content with the current lifecycle. Result: nested owners follow the same replacement/disconnect rules.
4. Build once with `npm run rollup` for the user's visual verification. Do not run the full build/test sequence before that verification.
5. #693: after visual acceptance, delegate bounded regression-test writing to Luna (max), review the tests, and run the final Node, lint, build and affected Chromium/WebKit checks. Result: permanent coverage for the real owner boundaries.

Each implementation subissue has its own branch and PR into the feature branch. Close it after merging. Merge the feature into master only after visual acceptance and final checks. Preserve the existing parent disconnect order and graph/path calculations.

## 8. Permanent tests

- old Sparkline history timer -> replacement/disconnect -> cancelled;
- old History result after replacement -> inert;
- old tool cleanup called before reference replacement;
- new tool immediately functional while parent remains connected;
- reconnect does not duplicate History/tool resources;
- idempotent cleanup.
- cleanup during drag does not submit a final action;
- nested content replacement closes old children and activates new children once;
- an accepted History completion that is queued when its owner closes remains inert.

Specialized pointer/Horseshoe assertions are added permanently in Plans 09/10.

The Plan 05 tests cover old-before-new tool and nested-content replacement,
Slider disconnect without a final write, Horseshoe animator cleanup, and a
History result accepted just before disconnect whose presentation is still
queued. Pointer cleanup tests cover cancelled frames, removed node/window
listeners, repeated disconnect and binding the reused SVG exactly once after
reconnect. Browser checks retain the existing geometry screenshot and verify
History timer cleanup and animation unbinding/rebinding in Chromium and WebKit.

## 9. Definition of Done

- replacement and DOM disconnect both reach old owner cleanup;
- History and existing concrete resource handles end through their functional owner;
- cleanup is idempotent;
- new tools receive correct current lifecycle when replacing inside a connected card;
- no central `ResourceManager`/registry exists;
- remaining pointer/path-specific defects are isolated behind stable cleanup entry points, not temporary compatibility code.

## 10. Guarantees for following plans

Following plans may assume:

- every tool/resource owner has a permanent cleanup entry path;
- config replacement closes old owners before constructing/activating replacements;
- specialized pointer/Horseshoe work only needs to correctly own its internal handles, not redesign CardTools lifecycle.
