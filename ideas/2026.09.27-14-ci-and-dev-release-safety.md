## Shared development prerelease

Use a single workflow-level concurrency group, `fhs-dev-latest`, with `cancel-in-progress: false`. The entire build/test/publish operation owns the lock. An active run finishes; a newer pending run replaces the older pending run. This is the user's selected policy, not a queue of every build.

Within one checkout, run `npm ci`, the existing full build, browser installation and all browser tests before replacing the prerelease. Upload that exact built `dist/flex-horseshoe-card.js`; do not rebuild or switch checkout during publication.

Required checks remain unconditional and failures stop publication. Release notes identify branch, source SHA, package version and workflow run URL. The general release-asset workflow excludes only `dev-latest`; other version releases keep their current behavior.

No new deployment framework, release manifest, rollback system, branch restriction or dependency/runtime upgrade belongs here.
