## Timezone policy

Initialize Node tests with `Etc/UTC` before loading tests. Use that explicit zone for UTC fixtures and the Playwright runner. Chromium and WebKit contexts use `Etc/UTC`; Firefox uses the equivalent browser name `UTC` because its timezone override rejects the alias. The Node zone avoids the container's observed `UTC` alias offset. Node 20 remains a usable local development environment; existing CI keeps Node 24.

Local-calendar tests explicitly select Europe/Amsterdam and restore the previous Date and timezone after execution. Retain spring's 23-hour day, autumn's 25-hour day, local midnight and existing numeric expectations. Fix test setup, not production calendar calculations.

## Shared development prerelease

Use a single workflow-level concurrency group, `fhs-dev-latest`, with `cancel-in-progress: false`. The entire build/test/publish operation owns the lock. An active run finishes; a newer pending run replaces the older pending run. This is the user's selected policy, not a queue of every build.

Within one checkout, run `npm ci`, the existing full build, browser installation and all browser tests before replacing the prerelease. Upload that exact built `dist/flex-horseshoe-card.js`; do not rebuild or switch checkout during publication.

Required checks remain unconditional and failures stop publication. Release notes identify branch, source SHA, package version and workflow run URL. The general release-asset workflow excludes only `dev-latest`; other version releases keep their current behavior.

No new deployment framework, release manifest, rollback system, branch restriction or dependency/runtime upgrade belongs here.

### Firefox finding and fix

Firefox's timezone override rejected `Etc/UTC`; its browser context now uses the equivalent `UTC` name. The test runner and Node fixtures still use `Etc/UTC`. Pointer fixtures install the controlled clock before its pause target and await the scheduled pointer frame.

The browser matrix then exposed incorrect screen-to-graph projection in Firefox. A minimal nested SVG, independent of the card, returned `(8, 8)` from the SVG viewport's matrix where Chromium and WebKit returned `(28, 48)`; the rendered group's matrix returned `(28, 48)` in all three browsers. Firefox omitted the nested SVG's `x/y` placement.

The user approved a separate bugissue and inclusion in this feature. #803 uses the already rendered plot group's matrix, bound with the existing pointer lifecycle, then converts back to the tool-local coordinates expected by pointer consumers. There is no browser detection or per-event DOM search. The regression targets the actual rendered content independently of the production conversion. All 12 pointer cases pass across the three browsers. The product-source change is three code lines and three functional comment lines.
