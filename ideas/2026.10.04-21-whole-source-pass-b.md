## Concrete Source Findings

### F1: Gate1 Can Retain An Older Action Client

**CHANGE: HA-context publication ownership; newly exposed by the early return.** [main.js](/workspaces/flex-horseshoe-card/src/main.js:173) `setHass()` publishes `_hass`, Templates, HomeAssistant and child cards before entering `updateSourceEntities()`. The Gate1 return at [main.js](/workspaces/flex-horseshoe-card/src/main.js:227) occurs before `actions.setHassAndEntities()` at line 253; the other action publication is in `updateEntityPresentation()` at line 348. Consequently a rejected HA delivery updates the card's client but leaves `CardActions.hass` at the previous accepted delivery.

[card-actions.js](/workspaces/flex-horseshoe-card/src/card-actions.js:23) stores that client, and `executeAction()` / `executeSliderAction()` use its `callService()` rather than reading the current card client. If only the HA connection/client or service callback changes while declared state, locale/display and theme references remain equal, a subsequent action uses the older client. This is a factual stale-reference path, not a claim that every ordinary HA delivery changes service callbacks. No live-HA reproduction was run. Parent decision is limited to keeping the action client's HA-context publication current without reopening rejected config/tool/render work.

### F2: Resolved By #904 Direct Mapping

**RESOLVED; mapping identities are no longer a contract.** Current [horseshoe-gauge.js](/workspaces/flex-horseshoe-card/src/horseshoe-gauge.js:513) `setState()` directly runs `getGaugeStateData()`, `buildStateMapDisplayLabels()`, `GaugeScale` and `PathValueMapper` construction. `runtime.mappingKey` and its equality branch are absent. The user's #904 decision supersedes the earlier theme-preservation interpretation: representative same-value cached/miss/miss/cached linear/spline/rank diagnostics found no consistent material CPU win. This sidecar did not execute those diagnostics.

[horseshoe-gauge.js](/workspaces/flex-horseshoe-card/src/horseshoe-gauge.js:726) `buildStateMapDisplayLabels()` consumes `hass.formatEntityState()` or `formatEntityAttributeValue()` and entity metadata. [home-assistant.js](/workspaces/flex-horseshoe-card/src/home-assistant.js:32) tracks formatter and registry references, opening Main Gate1 when those change. Direct mapping now refreshes these labels on that accepted state pass; the previous mapping-key suppression of formatter-derived labels no longer applies. Explicit authored labels remain authoritative; `rank_state` returns its authored map without this formatter path.

The former incomplete boundary existed at baseline `1669219` and during initial Pass B inspection. Record it as closed, not an outstanding review fix. Path geometry, path sampling and measurement caches remain independent retained owners; no assertion of mapping/scale object identity preservation remains in this report.

### F3: Legend Child-Reuse Key Omits Child Geometry Inputs

**KEEP a targeted child-publication boundary; CHANGE its input completeness. Inherited from baseline.** [sparkline-graph-tool.js](/workspaces/flex-horseshoe-card/src/sparkline-graph-tool.js:5838) `updateLegendTextTools()` creates Text config with absolute `xpos`/`ypos` from `geometry.svg.x/y` and ellipsis `max_width` from `textWidth / 2`. The `legendTextSignature` at line 5902 includes label, marker color, local marker/text coordinates and styles, but neither that max width nor the outer SVG origin.

A one-series bottom/top horizontal legend can change graph width while its first local marker/text coordinates and row height remain equal. The equality return at line 5915 then retains the old TextTool ellipsis limit. Likewise translating the graph with unchanged local legend layout can retain the old absolute TextTool position. Candidate children with the new values are constructed but never published on that return. The same producer and comparison exist in baseline source. This is not a generic render-only key: it protects disconnect/replacement, child initialization and new overflow measurement, so removal is not the audit recommendation.

## Corrections To The Earlier Audit

- **Measurement signatures do not skip all DOM work in `updated()`.** Name/Area/State always call `getBBox()` and read computed font sizes before checking measured changes. Text's settled width-overflow route reads `getComputedTextLength()` before comparing its result signature; its exact-bounds route reads BBox/font sizes before comparing tolerances. Sparkline's legend measured signature is compared after its BBox read. Retention saves invalidation, cancellation/restart, width layout/republication, dependent geometry and follow-up requests, not all of those reads.
- **Name/Area/State `setEffectiveStyles()` wrappers stay.** They implement the shared effective-style contract and call their measurement invalidator. Lack of a current product caller is not a reason to delete that shared, side-effect-bearing contract.
- **ControlNumber's retained key is more precise than the prior description.** `valueMeasurementSignature` compares the nested StateTool's input signature and resets `valueMeasurementPass`; `updated()` forwards value measurement for at most five passes. Centering consumes current exact/estimated geometry in `render()`. The key is not simply a cache of centering calculations.
- **Rectangle geometry is not protected only by config/group flags.** `render()` recalculates dimensions so a Text measurement correction can immediately update `fit` or referenced width/height without another HA/config pass.
- **Legend reuse does not avoid all candidate allocations.** `new TextTool(...)` runs before the equality check. Equal signatures prevent replacement/initialization of the accepted children and preserve their measurements/lifetimes, but the candidate constructor cost has already occurred. This is an inventory qualification, not an additional refactor request.
