# Home Assistant entity display formatters

## Goal

FHS should present entity names, attribute names, states and attribute values in
the same language and form as Home Assistant. Explicit FHS names and labels stay
authoritative, while automatic text comes from Home Assistant's formatter APIs.

This keeps cards compact, respects the user's locale and registry names, and
removes FHS copies of Home Assistant presentation rules.

## User-visible rules

- A Name tool shows Home Assistant's short entity name by default.
- A Name tool connected to an attribute shows Home Assistant's attribute name.
- `entities[].name` replaces the automatic name and accepts both a string and
  Home Assistant's structured entity-name configuration.
- An Area tool shows Home Assistant's area name unless `entities[].area` is set.
- Select options use Home Assistant's translated state or attribute value unless
  `option_map[].text` supplies an explicit label.
- State-map labels use Home Assistant's translated state or attribute value
  unless the map supplies an explicit label.
- A multi-series sparkline identifies a series with its area and short entity or
  attribute name, for example `Living room Temperature` and
  `Bedroom Temperature`.
- `series[].name` has priority over `entities[].name`, which has priority over
  the automatic series label.
- Legend and tooltip use the same series label.
- Values used for matching, actions and service data remain raw values. Only the
  displayed text is formatted.

## Home Assistant APIs

FHS uses the formatter that belongs to the displayed information:

| Information | Formatter |
| --- | --- |
| Entity name | `hass.formatEntityName()` |
| Entity state | `hass.formatEntityState()` |
| Entity state parts | `hass.formatEntityStateToParts()` |
| Attribute name | `hass.formatEntityAttributeName()` |
| Attribute value | `hass.formatEntityAttributeValue()` |
| Attribute value parts | `hass.formatEntityAttributeValueToParts()` |

The State tool keeps using the `ToParts()` APIs so values, signs, literals,
currencies and units retain Home Assistant's order.

## Ownership

Each presentation tool asks Home Assistant for the text it owns. There is no
generic FHS formatter manager and no fallback to `friendly_name`, entity ids or
the former copied state formatter.

The sparkline tool owns one `formatSeriesName(item)` operation because legend
and tooltip must share exactly the same naming rule.

## Home Assistant lifecycle

Displayed text can change without an entity state change. A locale change, a
registry update or replacement of a formatter function therefore belongs to the
card's Home Assistant context lifecycle.

The `HomeAssistant` class records changes to:

- locale;
- formatter function references;
- entity, device, area and floor registry object references.

Those changes run the existing full Hass-context update. The marker is cleared
after every context-dependent card domain has processed it.

## Compatibility

The direct formatter contract requires Home Assistant 2026.4 or newer. Missing
formatter APIs are not handled later in rendering code; compatibility belongs
to the supported-version contract.

## Regression tests

Tests should prove:

- short entity, attribute and area names use the corresponding HA formatter;
- explicit string and structured names retain priority;
- select and state-map labels are translated without changing their raw values;
- legend and tooltip use identical, distinguishing series names;
- locale, formatter and registry reference changes trigger a context update;
- unchanged Home Assistant context does not trigger another context update;
- State tool part formatting remains unchanged.
