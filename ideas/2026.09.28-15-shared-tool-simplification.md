Remove low-risk repeated tool boilerplate before changing the configuration boundary.

This plan deliberately starts with mechanical duplication whose behaviour is already established. It must leave a working card and provide a smaller, clearer base for Plan 16.

Baseline locators refer to `44eac7b6cb9d93e6b76a10f801576f052788d44e`.

## 5. Scope

### 5.1 Shared coordinate calculation

Provide one common default coordinate calculation in the existing shared owner.

Concrete tools keep an override only when they add real geometry.

Do not introduce a geometry service or registry.

### 5.2 Measured geometry getters

Move the four identical getter behaviours to one small, explicit text-geometry helper. The current consumers are `CardTools` and ControlNumber. Remove the sixteen redundant getters from Name, Area, State and Text after migrating those consumers. Do not add measured-text methods to `BaseTool`: shape and control tools do not own text measurements. Total product code must still decrease.

### 5.3 Icon group transforms

Allow the existing BaseTool transform/style methods to accept an optional item config if required by IconTool, then remove IconTool forwarding copies.

### 5.4 Section construction

Remove identical class-level `setConfig()` factories only when `CardTools` can construct the same arrays directly with a small obvious helper or equally clear direct code.

Do **not** build a generic tool registry, metadata schema or reflection-based factory.

Special setup remains with its current owner.

## 6. Out of scope

- Sparkline config validation.
- Horseshoe path validation.
- Control config validation.
- text measurement algorithm changes;
- State formatting;
- render order;
- YAML changes;
- config gatekeeper changes.
