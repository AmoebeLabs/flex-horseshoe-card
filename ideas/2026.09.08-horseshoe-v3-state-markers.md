# Horseshoe V3 state markers

## Goal

A horseshoe can show its current value as a filled part of the path, as a marker at the current position, or as both. The same configuration works for every Horseshoe V3 path shape.

The marker is another presentation of the current state. It therefore uses the existing horseshoe state color, color stops, styles, color filter, and animation instead of introducing a separate appearance system.

## Basic configuration

```yaml
layout:
  horseshoes:
    - entity_index: 0
      show:
        state_progress: true
        state_marker: true

      horseshoe_marker:
        attach_to: path
        icon: mdi:dots-horizontal
        rotate: 0
        offset: 0
        size: 8
```

`state_progress` is enabled by default to preserve existing cards. `state_marker` is disabled by default.

The two options are independent:

| Result | `state_progress` | `state_marker` |
| --- | --- | --- |
| Filled path | `true` | `false` |
| Marker | `false` | `true` |
| Filled path with a marker at its leading edge | `true` | `true` |
| Scale without a state indication | `false` | `false` |

## Marker on the path

`attach_to: path` places the marker at the current value on an arc, line, rectangle, polygon, wave, spiral, or infinity path. The marker follows the path direction. `rotate` corrects the source icon orientation and `offset` moves it beside the path.

A path marker without an icon uses a circle. Its default size follows `horseshoe_state.width`, so a simple marker needs only:

```yaml
show:
  state_progress: false
  state_marker: true
```

A triangle is available as a second built-in shape. A configured marker can instead use an `mdi:` icon, an external SVG in `url(...)`, or a PNG, WebP, or JPEG in `url(...)`.

## Marker from the center

`attach_to: center` gives an arc a hand or pointer from its center toward the current value. It requires an icon because the icon shape determines how the pointer looks.

```yaml
show:
  state_marker: true

horseshoe_marker:
  attach_to: center
  icon: mdi:arrow-up-bold
  rotate: 0
  aspectratio: 8
  start_offset: 4
  end_offset: -2
```

The marker fills the available distance between `start_offset` and `end_offset`. `aspectratio` controls how narrow the pointer is without requiring an absolute size. Positive offsets move outward from the center; negative offsets move inward.

An icon that points upward uses `rotate: 0`. Use `rotate` to correct an icon that has another natural direction; for example, `mdi:bow-arrow` uses `rotate: -45`. The pointer then follows the current value around the arc automatically.

## One state animation

The existing `PathStateAnimator` remains the only owner of animated progress. During each animation frame it supplies one 0..100% position to both visible state layers:

1. Render the filled progress path when `state_progress` is enabled.
2. Render the marker at the same position when `state_marker` is enabled.

This keeps a marker at the leading edge of the progress path without a second timer or a second value calculation.

## Geometry and sources

- The measured master path remains the only source for marker position, tangent, and normal.
- Path markers reuse the existing path-element geometry instead of implementing path-specific calculations.
- Center markers use the center and current point of an arc path.
- Home Assistant icons and external files reuse the card's existing icon and URL caches.
- An unresolved icon stays hidden until its source dimensions are known. Loading it does not restart the state animation.
- Vector markers receive the calculated state fill and stroke. Raster markers preserve their image colors and receive applicable group opacity and filters.
