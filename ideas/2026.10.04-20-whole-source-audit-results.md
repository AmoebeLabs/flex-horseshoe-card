## 1. Implemented Changes

- Runtime entity and group configuration use `runtimeEntityConfigs` and
  `runtimeGroupConfigs` consistently through their actual consumers. Static
  compiler entity resolution retains its separate meaning.
- `runtimeConfigInitialized` describes completion of the first runtime-config
  update, rather than existence of constructor config. `evaluatedConfigSignature`
  retains the existing skipped-translation behavior for equivalent JS output.
- External SVG request reset is named `clearPendingRequests()`. Stale-result,
  disconnect and target checks remain unchanged.
- Unread HomeAssistant/Theme fields and duplicate theme-mode storage are removed.
  Theme comparison uses `colorContext.mode`; the consumed `modeChanged` signal
  and the HA reference used by view observers remain.
- Palette loading consumes the object already supplied by its caller. URL
  caching, generations, mode application and removal of old CSS variables remain.
- Child tools receive entities through their existing `setEntities()` method.
  The CardTools pass-through wrapper and duplicate Control label-presence flag
  are removed, without changing invocation order or binding arguments.
- Toggle preset icon entries without renderer or JS-source consumers are removed.
  A focused template-context test establishes that those preset entries were
  already absent from `item`; authored icon entries remain usable.
- The obsolete commented StateTool formatting pipeline is removed. Live state
  formatting and measurement signatures remain. Functional comments describe
  the current Text, BaseTool, Graph and path-mapping routes.
- Unused dimension/math exports and the unused Utils interpolation method are
  removed. Live interpolation remains in Colors. Empty historical CSS and
  commented debugging/speculation are removed without changing executable
  template/merge behavior.
- Test-only Series row assignment, Graph history setter, path-element getter and
  value-mapper mutator are removed. Tests use the same row update route, existing
  measured DOM element and mapper construction used by production.
- The unused `path-renderer.js` arrangement is moved to
  `tests/fixtures/path-renderer.js`. Its Node and browser tests still exercise
  the production `path-mask-renderer.js`, including caps, borders and opacity
  overlap. It is no longer counted as product code.
- The accidental `layout.horseshoes_v2` route is removed from the gauge factory,
  section registry, ordering constants, YAML schema sources, generated schema,
  active v12/validator copies and current compatibility guidance. The regular
  `layout.horseshoes` route and original root-level configuration remain tested.

No functional algorithms, JS evaluation order, source-visible defaults, HA
state handling, rendering policy, measurement rules or public feature behavior
have been redesigned. Alias removal is the explicitly approved exception.

## 2. Preserved Ownership Chains

Ordinary tools and Controls keep:

```text
compiled source -> sourceConfig -> owning JS evaluation -> local newConfig
-> existing translation/completion -> this.config
-> geometry/runtime/paint -> rendering and interaction
```

Text retains one source/current owner with two evaluation contexts: outer config
and per-part fields. Inline source tools receive evaluated entity bindings before
state assignment. Child final styles and font-related measurement invalidation
retain the existing route.

Sparkline retains:

```text
current tool config -> Series items/plot plan -> History request/prepared rows
-> Graph bins/statistics/geometry -> tool paint/render
-> derived entity output -> ordinary presentation consumers
```

Horseshoe retains:

```text
current gauge config -> scale/value mapping -> path definition
-> browser-measured PathGeometry -> positioned elements/paint
-> rendering; animation updates the state layer and marker
```

Theme changes update active paint through the shared color context. History and
mapping/geometry owners retain their concrete reuse keys. The #885 derived-series
palette precedence remains intact.

## 3. Retained Mechanisms and Plan 21 Boundary

| Mechanism | Concrete purpose and decision |
| --- | --- |
| Evaluated-config signature | KEEP: equivalent JS results avoid repeated translation; group/theme changes still run their own phase. |
| Text config/measurement signatures | KEEP: independent part contexts and effective font styles invalidate actual width/overflow measurement. |
| History request identity, ranges and generations | KEEP: reject stale requests and protect reconnect, retry and larger-window loading. |
| History conversions and Graph data revisions | KEEP: retained rows/bins avoid repeated conversion and aggregation on live updates. |
| Series layout and palette calculation keys | KEEP: shared axis/geometry work and semantic scale/rank changes are distinct from color-only changes. |
| Horseshoe mapping, path and measured-gradient keys | KEEP: theme/state changes reuse mapping, DOM measurements and adaptive path sampling. |
| Animator generation/frame lifecycle | KEEP: interrupted/disconnected animation cannot paint obsolete frames. |
| Palette URL cache, load generation and view observer | KEEP: avoid duplicate fetches and apply only current CSS inheritance/mode results. |
| Generic presentation signatures and paint/style indirection | DEFER: Plan 21 reviews the live render/update policy. Current storage and identity are not immutable product contracts. |
| Guards for external HA/DOM/network data and reachable algorithm cases | KEEP where their actual runtime purpose remains; no generic configuration gatekeeper is introduced. |

The label state relation remains local to label selection: it serves selected
label values, while painted ranges serve drawn intervals. This audit does not
merge those algorithms merely because their relation names resemble each other.
