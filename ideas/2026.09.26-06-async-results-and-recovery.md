# 06 - Async results and recovery

Reviewed on 2026-09-26 against master `1fc9c7b0c9cc6f19d8e61fe9d3bd52e4bd020293` (5.4.7-dev.32).
Feature issue: #699. Feature branch: `699-async-results-and-recovery`.

## 1. Goal

Publish non-History asynchronous results only while their operation is current, recover from transient palette failures, and end obsolete work during replacement or disconnect.

## 2. Prerequisites

Plans 01-05 are complete. History owns request validity and retry; CardTools and composite owners now forward replacement/disconnect cleanup. Read the master plan and shared `refactor/TESTING.md` before implementation.

## 3. Current-code validation

The review reproduced three defects without editing production code: two failed palette loads share one permanently rejected promise; palette A completing after B reapplies A; child config A completing after B publishes A. It also reproduced a deferred TextTool measurement publishing after disconnect and a hold dispatch after element removal. Icon path polling has no cleanup hook; SVG callbacks unconditionally publish.

History validity from plan 05 is retained. Initial configuration can be assigned before the first DOM connection, so validity cannot be reduced to a blanket `isConnected` check.

## 4. Scope

Palette cache recovery and CardTheme publication; ChildCards creation and frameless follow-up; entity/icon-path and external SVG sources; deferred text/gradient measurement; delayed gesture cleanup. The user chose gesture cleanup here so plan 09 remains Sparkline-specific.

## 5. Out of scope

Generic async/resource managers, new YAML, Graph/path/marker mathematics, History redesign, automatic retry polling and release/workflow changes. Palette completion keeps the current card propagation until plan 07; theme-aware color-cache architecture stays in plan 12.

## 6. Required behaviour

- Each concrete owner compares its live operation and current source/config before publishing. Disconnect invalidates old operations even when they finish after reconnect.
- Configuration before the first connection remains valid. DOM work requires the current committed node.
- Own/cancel timers and RAFs. Non-cancellable promises may settle but obsolete callbacks cannot publish, render or clear newer scheduling state.
- Reconnect retains accepted sources and resumes only current incomplete work once.
- Errors remain observable; a failed shared cache entry is evicted only when it still belongs to the same request.
- External SVG loading retains SVGInjector, but injection runs on detached staging nodes. Only a current operation can cache/publish into its real placeholder.
- Use existing functional vocabulary, linear logic and explanatory inline comments; validation/defaults remain in configuration/constructors.

## 7. Implementation sequence

1. #700: palette promise sharing/failed-entry eviction plus latest-operation CardTheme publication and lifecycle. Result: failure can retry and old palettes cannot overwrite current CSS/state.
2. #701: stage ChildCards locally; verify currency after helpers, creation, render waits and each frameless retry. Result: completion order cannot replace the latest children or alter obsolete DOM.
3. #702: current entity-icon/path requests, owned polling cleanup and staged external SVG publication; forward IconTool/marker lifecycle. Result: source replacement/disconnect cannot publish obsolete icons; geometry remains identical.
4. #703: text content revision/current measurement/DOM identity plus owned gradient RAF cleanup. Result: old measurements are inert and current text still measures on reconnect.
5. #704: AsyncDirective gesture lifecycle, stable listeners and timer cleanup. Result: delayed tap/hold cannot fire after removal; options changes cancel only changed gestures.
6. Build once with `npm run rollup` for user visual verification.
7. #705: after visual approval, Luna (max) writes bounded permanent tests; review/integrate and run final Node/lint/build and affected Chromium/WebKit checks.

Each subissue has its own branch/PR into the feature branch and closes after merge. Do not merge the feature into master until visual and final regression acceptance. Commit this reviewed plan together with the software changes.

## 8. Permanent tests

- Palette concurrent success/failure, network/HTTP/JSON failure recovery, exact-entry eviction and old rejection versus newer request.
- CardTheme/ChildCards A/B in both completion orders, removal of config and disconnect/reconnect; include deferred frameless callbacks.
- Icons: source switches, shared consumers, retry, disconnect/reconnect and obsolete SVG callbacks.
- Text/gradients: fonts-ready/RAF after replacement/disconnect, new measurement while an old one completes and reconnect.
- Gestures: hold/delayed tap during removal, actual option changes and reconnect without duplicates.
- Keep real FHS neighbours; mock only network/time/DOM boundaries. Real Chromium/WebKit cover DOM binding, staged SVG publication, text measurement and gesture lifecycle. Preserve History and Graph/path invariants.

## 9. Definition of Done

Old results are inert, failed sources can retry, current failures remain visible, reconnect duplicates no owned work and all required final checks pass. No generic async framework or temporary propagation bridge is introduced.
