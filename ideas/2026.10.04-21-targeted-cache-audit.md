# Plan 21 Targeted Cache Audit

## Scope and Status

Issue #904 audits caches that protect data processing, geometry or browser measurement. The immutable baseline is `16692192a33dd3423387ea99087c7d4b9447d5f8`. This report records the implementation decision before the visual checkpoint; final A-I comparisons remain pending.

## Horseshoe Mapping Decision

Remove `runtime.mappingKey` and calculate current state mapping directly in `setState()`.

The key serialized entity state/attribute, state mapping, scale configuration, bar mode, zero position, state mode, locale and color-stop thresholds on every call. Ordinary changing values already invalidated it. Its useful case was unchanged mapping input, including theme-only updates.

The diagnostic runs the baseline's real `setState()` unchanged, comparing normal cache hits against a forced key miss. Cached/miss/miss/cached order reduces first-pass compilation bias. Each pass has 40 warm-ups and 1,000 measured updates. No final A-I workload was changed.

| Mapping | Cached CPU, passes 1/4 (ms) | Forced-miss CPU, passes 2/3 (ms) | Mapper builds per measured pass, hit/miss |
| --- | ---: | ---: | ---: |
| Linear | 36.148 / 20.255 | 23.763 / 22.603 | 0 / 1,000 |
| Spline | 24.195 / 18.904 | 24.687 / 20.703 | 0 / 1,000 |
| Ranked | 30.378 / 34.308 | 36.309 / 30.681 | 0 / 1,000 |

The cache prevents reconstruction but does not show a consistent material CPU benefit for these representative fixtures. Small differences are within the observed ordering/timing variation. They are not a claimed speedup or a universal bound for larger custom scales. Removing the key simplifies the local route without changing mapping results; final P21-I checks the integrated outcome.

Raw evidence: `tests/performance-results/2026.10.04-plan21-mapping-cache-diagnostic.json`. Runner and reproduction details: `tests/performance-mapping-cache.mjs` and `tests/PERFORMANCE.md`.

P21-I continues recording mapper/scale identity changes for both builds. Their identity is no longer an acceptance requirement. Path geometry and SVG measurement reuse remain requirements.

## Retained Work Owners

| Producer / consumer | Retained inputs and result | Work avoided and reason |
| --- | --- | --- |
| Sparkline History / Series and Graph | Request identity/generation, retained ranges/rows, conversion and processed-data revisions | Network requests, stale-response publication and historical conversion/aggregation remain owned here. Rendering does not duplicate this work. |
| Sparkline Graph/Series / layout and SVG consumers | Palette calculation and shared series layout signatures, graph geometry inputs | Scale/layout/path calculation remains protected independently of the removed presentation gate. Theme colors may change without rebuilding historical bins. |
| Day/night History / Sparkline background rendering | Sun entity identity and request generation | Sun history/forecast ownership remains independent; implicit `sun.sun` changes still reach the card input gate. |
| Path geometry / Gauge, ticks, labels, gradient and marker consumers | Definition/transform, browser length/point/tangent measurements and bounded temporary samples | Prevents repeated SVG measurement and geometry generation during rendering and animation. |
| Horseshoe / Path gradient and element rendering | Measured gradient inputs, scale/background layout and path-element geometry keys | Reuses static geometry while progress and theme paint change. These are not generic render comparisons. |
| Text / DOM measurement and text-fitting shapes | Effective outer/part styles, text content and measured-width dependencies | Measurement ownership remains local; animation styles are published before current text is measured. |
| Async resource owners / targeted completion | Request/source generations, animation frames and connection state | Prevents stale async writes and keeps completions bounded to their owner. |

The 71-module Pass B provides the per-module cross-check. No History, Graph, Series or Path cache algorithm was rewritten in this subissue.
