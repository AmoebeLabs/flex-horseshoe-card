# Plan 15B - Reference Architecture and Simple Tools

Date: 2026-10-01. Baseline: `dd89eb08f029400730ce59a4112be34bba44deeb`.
Parent issue: #832. Featurebranch: `832-canonical-simple-tool-configuration-and-geometry`.

## Goal and Functional Boundary

Use Arc and Icon as the reference for consistent tool configuration ownership,
then migrate the remaining simple shapes and measured entity text. Preserve
public YAML, JavaScript evaluation context/order, shape calculations, formatting,
paint precedence, animation and connection lifecycle.

`sourceConfig` is the stable template-visible source, including defaults that
JavaScript already sees. `newConfig` is local. `this.config` is the only current
general configuration. Derived dimensions belong to `geometry`; displayed
content belongs to `runtime`; parent-driven presentation belongs to `paint`.

Rectangle's correction after text measurement is required functional behavior.
Keep its timing and calculation, changing only the destination to `geometry`.
Do not freeze fit geometry at configuration time.

## Interfaces and Staging

- Supply pure tool translation explicitly to BaseTool, never dispatch into a
  subclass override during the BaseTool constructor.
- Preserve existing pre-evaluation defaults and the moment HA-backed JS runs.
- Rebuild tool geometry on configuration/group changes, not theme-only changes.
- Pass tool SVG geometry separately into the group transform-origin route.
  Keep the existing path usable by families that have not migrated yet.
- Move Polygon path inputs/definition into geometry; leave generator math alone.
- Use `runtime.name`, `runtime.area`, `runtime.state`, `runtime.uom`.
  Common BaseTool entity context remains unchanged until Plan 16B.
- `setPaintStyles(styles)` publishes or clears a complete `paint.styles`
  replacement. Renderers apply the existing animation/filter/color cascade.
- Preserve current selected-child style merge priority. Controls migrate in 17B;
  TextTool completes effective-style measurement integration in 16B.
- Retain `text-tool-geometry.js` as the single bridge between migrated measured
  tools and the current TextTool geometry until 16B.
- Shared active color-stop storage remains unchanged until the atomic Plan-19
  integration. Do not duplicate it under config and paint.

## Execution Results

### Implementation

- Arc, Circle, Line, Rectangle, Polygon and Icon now publish derived SVG
  dimensions through `geometry.svg`. Polygon also owns `geometry.pathInput`
  and `geometry.pathDefinition`.
- BaseTool accepts an explicit pure translator. The existing constructor-owned
  source defaults remain visible to JS; unchanged evaluated config retains its
  identity and skips translation. Line, Rectangle and Polygon use the same
  local translation rules initially and for changed JS results.
- Name, Area and State own displayed content in `runtime` and measurement data
  in `geometry`. Their formatting and measurement calculations are retained.
- `setPaintStyles()` replaces or clears presentation styles without changing
  configured styles. Measured text invalidates bounds only when effective
  text/style signatures change.
- Group transform origins receive geometry explicitly. The existing TextTool
  adapter remains the sole measured-text bridge until Plan 16B. Rectangle keeps
  its render-time correction after browser text measurement.
- Cross-caller review updated ControlNumber's StateTool center/signature reads
  and Sparkline's StateTool tooltip formatters. These are field-path changes;
  neither consumer's behavior or own storage architecture is redesigned here.
- Three Luna Max agents handled disjoint shape, measured-text and test work;
  the main agent owns BaseTool, Icon/Arc and caller integration.

## Follow-Up - Icon Paint and State-Map Precedence

Date: 2026-10-02. Issue: #840. Branch:
`840-preserve-icon-state-map-styles-with-parent-paint`.
Baseline: the Plan-15B merge `83c6206e11454a456a665891f13222ad4636d7c1`.

The subsequent implementation review found a combination missed by the original
post-review above: selecting `paint.styles` bypassed Icon's selected
`state_map.styles`. No production parent calls the new paint API yet, so this
was a dormant interface defect rather than an observed card regression.

### Bounded Correction

- Icon first selects the complete parent-resolved style map (or its normal
  configured/state-map render styles when parent paint is absent). When parent
  paint is present, it overlays the selected map's styles locally before the
  existing color-stop and animation pipeline.
- The order is parent-resolved child paint, state-map styles, color stops,
  animation, then existing final render processing. Non-style state-map fields
  continue to use the same transient `renderItem`.
- BaseTool's API comment now specifies complete parent-resolved replacement
  styles, not partial overrides. The parent retains its existing merge priority;
  BaseTool does not merge configured styles into that result again.
- Controls and TextTool are not migrated here. Their planned 17B/16B work must
  preserve existing child/part/state-map priority when connecting parent paint.

### Regression Evidence

Before the fix, the focused Icon test failed with actual fill `#1565c0` (parent
child/base paint), versus expected `#d32f2f` (selected state-map paint). After the
single render overlay was added, the same test passed.

The Node case covers configured child styles, a realistically parent-merged map,
selected map styles, active color-stop paint and final animation precedence.
It also covers absent selection, clearing parent paint and unchanged config,
source and parent style dictionaries. The BaseTool replacement test now includes
the real parent merge order, while retaining an explicit deliberate-omission
case to prove that replacement is not an implicit merge.

The browser regression checks rendered Icon fill/color/opacity with parent paint
and after clearing it. The existing measured-text paint case now publishes a
complete map and still checks geometry and Rectangle fit.
