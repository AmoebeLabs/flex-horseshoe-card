# 13 - Final simplification and cleanup

## 1. Goal

Remove confirmed unused code and outdated explanations left after the architecture refactor. Keep the current data, geometry, paint and lifecycle owners, public YAML and established browser behavior intact.

The expected improvement is a smaller maintenance surface and a more readable implementation. Removing unused code is not a promise of faster rendering: Rollup may already eliminate some unused code from the bundle.

## 2. Prerequisites

Apply `ideas/refactor/00-master-refactor-plan.md` and `ideas/refactor/TESTING.md`. Plans 01 through 12 are integrated in master. Plan 14 remains the separate CI/release-hardening step.

Baseline: synchronized master `a8abf385036356a0e20bdfbb5ac7bf828c21cfb0`, version `5.4.7-dev.32`. Preserve the user's local Plan 00 edits. Do not merge into master without explicit approval.

## 3. Current-code validation

The original plan's internal Hass feedback route and mutable global color host have already been removed. Their absence is a final review check, not another implementation task.

Current candidates were checked against production source, tests and documented configuration:

- Colors contains old theme/palette processors, two unused color-stop calculation routes and an unused Lovelace lookup wrapper. Current CardTheme/Palette publication and context-aware Colors conversion remain active.
- ConfigHelper and SameAs retain unused normalization/merge wrappers. Remove only those with no callers; preserve existing field-specific normalization and merge behavior.
- ControlContent stores two constructor inputs that are used locally but never read from the instance. GraphTool and Graph also contain write-only fields.
- GraphTool retains separate, uncalled line-minmax renderers, an old mask wrapper, axis wrappers and an old pointer wrapper alongside the current routes.
- Graph retains a few old helpers used only by direct tests or not at all. Move meaningful behavioral coverage to the current data/geometry route before removing a test-only helper.
- Some comments describe temporary history presentation or older implementation choices rather than the current explicit data states.

Treat this as a removal inventory, not an automatic unused-code detector. Check bracket/string dispatch, framework entry points and tests before every removal. Keep meaningful published results even when their consumers are currently tests.

## 4. Scope

Confirmed unused helpers and fields, obsolete Sparkline routes, functional English headers/inline comments and the minimum test changes needed to preserve behavior through current owners. Update the plan index and shared developer terminology where it describes the affected route.

## 5. Out of scope

- New shared text-measurement or radial/cartesian architecture.
- Graph/path formulas, path generators, Safari interaction workarounds and color/filter algorithms.
- Public YAML, defaults, broad naming changes or new runtime fallback checks.
- Removing request identity, lifecycle validity or DOM-measurement guards merely because they are flags.
- CI workflows, release policy, version bumps, unrelated bug fixes or edits to the user's Plan 00 work.

## 6. Required design and behavior

Follow the existing forward update flow. Main owns external HA entry and render scheduling; History owns accepted rows, ranges and request validity; Series coordinates normalized series and shared plot geometry; Graph produces retained per-series calculations; GraphTool renders and owns pointer interaction. CardTheme publishes prepared color context and Colors owns conversion/reuse. PathGeometry and PathStateAnimator retain measurement and animation ownership.

For each removed route, identify its current replacement and all consumers. Confirm the producer, stored output and recalculation triggers together, including implicit single-series and explicit series. Remove unused calculations rather than introducing another accessor or compatibility route.

Existing text measurements have different inputs and responsibilities, particularly StateTool's unit placement and TextTool's measured parts. Keep them local. Existing cartesian/radial calculations also remain explicit. Similar-looking code is not sufficient reason to introduce another layer.

Preserve same-input calculation outputs and paint-only/data/geometry boundaries. Keep framework callbacks, async request protection and cache lifetime checks. Comments explain the user-visible purpose, required order and reuse of the following block in ordinary English.

## 8. Permanent tests

Keep existing behavior tests and numeric/screenshot baselines. For an intentionally removed private helper, first prove the same observable result through the active owner and move the assertion there. Remove only implementation-shape assertions that no longer describe an active interface.

Acceptance includes:

- Current calendar/rolling data, offsets and long-short-long period changes.
- Line/area/minmax, implicit and explicit series, current derived values and tooltips.
- Pointer lifecycle, retained SVG nodes and radial/cartesian selection.
- Theme/mode/palette changes and reused graph/path calculations.
- Horseshoe gradients, animation and marker lifecycle, including WebKit-sensitive routes.
- Full Node tests, lint, complete configured Chromium core and required WebKit cases according to the shared policy.

Use existing integration tests for one calculation per required input and zero normal data/geometry work on paint-only updates. No temporary cleanup-only suite, arbitrary performance target or expanded screenshot matrix.

## 9. Definition of Done

The confirmed unused routes/fields are gone; active guards and prepared result interfaces remain. Comments explain current behavior. Public configuration, proven formulas and browser behavior are preserved. No new owner or compatibility path is introduced. Required acceptance passes and the final producer/result/consumer/trigger review has no unresolved findings within this scope.

Any unrelated defect discovered during verification is recorded separately with its owner, rather than folded into cleanup silently.

## 10. Guarantees for following plans

Plan 14 consumes the completed runtime refactor and hardens test/release execution. It does not repair removed runtime ownership boundaries. Current prepared inputs, retained calculations, explicit data states, forward local updates and color context remain stable.
