# Sparkline radial chart

## Goal

Add `chart_type: radial` with `line`, `area`, and `dots` variants while keeping radial barcode and the new chart on one geometry contract.

The implementation must preserve the existing sparkline layers:

| Layer | Responsibility |
| --- | --- |
| `SparklineGraphTool` | Configuration, history lifecycle, SVG presentation, axes, legend, tooltip, and interaction events. |
| `SparklineSeries` | Series collection, shared bins, shared value ranges, axis assignment, and graph coordination. |
| `SparklineGraph` | Bucket geometry, polar angles, radii, paths, arc geometry, and pointer-to-bin projection. |

`SparklineSeries` does not calculate polar coordinates. `SparklineGraphTool` renders the points and paths returned by `SparklineGraph`.

## Public configuration

```yaml
sparkline:
  show:
    chart_type: radial
    chart_variant: area # line, area, dots
    fill: fade

  radial:
    arc_degrees: 270
    rotate: -135
    size: 15
```

The same `sparkline.radial` geometry is used by `radial` and `radial_barcode`. Defaults remain in the sparkline tool configuration:

```yaml
radial:
  arc_degrees: 360
  rotate: 0
```

## Geometry contract

- Time advances clockwise from `rotate` across `arc_degrees`.
- Every history bin has one angle on that arc.
- A value is converted to a radius with the graph's active Y-scale.
- `size` defines the distance between the shared inner and outer radius.
- Radial barcode uses the same center, radius, arc, rotation, and bin angles.
- Pointer lookup converts the pointer angle back to the same bin index.
- A partial current period has no pointer result beyond its available buckets.
- A radial area closes against zero, or against the nearest visible scale boundary when zero is outside the scale.

## Series contract

An implicit one-entity radial chart and an explicit radial series list use the same coordinator. Explicit radial series may combine `line`, `area`, and `dots` through `chart_variant`.

Cartesian and radial geometry are not mixed inside one `series:` list. Each radial series can still override its color, line, dots, area, period offset, and Y-axis assignment.

## Axes and interaction

- X grid lines become time spokes.
- Y grid lines become concentric arcs.
- The X-axis follows the outer arc.
- The primary Y-axis uses the start of a partial arc.
- The secondary Y-axis uses its end.
- On a full circle, the secondary Y-axis is opposite the primary axis.
- X and Y labels remain horizontal.
- Tooltip rows and source timestamps use the existing series tooltip.
- The active indicator is a spoke through the selected bin.

## Implementation stages

1. Introduce engine-owned radial geometry and move radial barcode onto it.
2. Add line, area, and dots paths to `SparklineGraph`.
3. Coordinate radial series, shared bounds, bins, and margins in `SparklineSeries`.
4. Render radial variants, value colors, and area fade in `SparklineGraphTool`.
5. Add radial axes, grid, labels, pointer lookup, tooltip, and active indicator.
6. Add engine, coordinator, renderer, showcase, and documentation coverage.

## Verification

Automated tests cover:

- partial arcs and rotation;
- shared barcode and radial geometry;
- line and area paths;
- pointer-to-bin lookup;
- primary and secondary radial axes;
- radial-only series validation;
- shared series bounds and margins;
- area fade around zero.

The interactive showcase combines line, area, dots, dual Y-axes, legend, tooltips, arc changes, rotation changes, and axis visibility in one card.
