## 1. Goal

Keep moving path measurements bounded and reuse prepared geometry throughout the Horseshoe update/render route. Preserve existing YAML, path mathematics, colors, markers and animation behaviour.

## 2. Prerequisites

Read the master refactor plan and shared `TESTING.md`. Plans 05, 06 and 08 already provide resource cleanup, asynchronous result validity and targeted presentation updates. Extend those existing owner boundaries rather than replacing them.

## 3. Current-code validation

- A 1,000-position moving-marker reproduction grows the permanent point cache from 201 to 1,201 and adds 1,000 permanent tangents.
- A 1,000-position current-gradient reproduction retains 3,583 permanent points.
- A fixed-scale full gradient rebuilt after state 25 changes to 75 has new range objects but numerically identical geometry.
- Horseshoe disconnect already unbinds the animator, cancels its frame and releases its master node; measurements remain reusable after reconnect.
- Trace the producer, stored result, consumers and recalculation inputs together, including moving markers, current/full gradients, static labels, ticks, backgrounds and transformed geometry.

## 4. Scope

PathGeometry owns browser measurement and reusable samples. Gradient calculation produces prepared adaptive intervals and coordinates; paint consumes those results. HorseshoeGauge retains the results and compares their effective inputs. PathStateAnimator owns one active transition and its frame. Renderers consume prepared geometry; only moving state presentation changes during animation.

## 5. Out of scope

No YAML additions, path-mathematics rewrite, progress rounding as a cache workaround, global cache manager/LRU, icon-source redesign, Sparkline processing changes or CI/release workflow changes. Change DOM structure only after a focused browser reproduction proves accumulation.

## 6. Required behaviour

- Preserve permanent measurement reuse for fixed positions and path signatures.
- Add explicit temporary sampling for moving positions. Reuse points and directions for equal drawing inputs; replace temporary storage when those inputs change.
- Transformed geometry forwards the same sampling choice. Marker points, tangents and normals reuse one measurement result rather than independently sampling it.
- Separate adaptive gradient geometry, color application and the visible reveal range. Identical geometric inputs share one prepared result across applicable state, scale and background layers.
- A full gradient retains its geometry across numeric updates. Only its visible range changes. Paint-only color/opacity changes retain measured geometry.
- A current gradient recalculates when its visible domain changes and retains only its current layout, not a history of frame layouts.
- Recalculate color distribution when scale mapping, active absolute branch, palette or color filter actually changes; external palette completion remains effective.
- Retain transformed geometry while the path signature and affine transform remain equal.
- Stop old animation before losing its path/DOM binding. Retarget from displayed progress; repeated targets and repeated binding do not restart timing. Changed styles still appear on a reused mount.
- Preserve owner cleanup and reconnect through Plan 05. No animation frame enters normal card/history processing or rebuilds static path layers.
